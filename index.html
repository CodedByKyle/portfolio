SpecCheck

A pre-production spec sheet checker for a home decor manufacturer that supplies Target, Walmart, CVS, Kohl's and other national retail chains.

It reads spec sheets locally, checks spelling, dimensions, fonts, finishes, materials, header fields, product data and factory information, and sorts every file into a review report before anything goes to manufacturing.

Case study Problem, workflow, stack

Problem

Before a product is manufactured, its spec sheet has to be right: spelling, dimensions, fonts, finishes, materials, header fields, product data and factory information. A wrong value that gets past review can carry into production.

SpecCheck adds an automated first pass to that review and leaves the decision with a person.

Workflow

  1. InputBox link Box APILocal folder
  2. ReadEach file opened on the local machine, with text recognition (OCR) for image-based sheets
  3. CheckSpelling, dimensions, fonts, finishes, materials, header fields, product data, factory information
  4. SortHoldReviewCleanUnreadable
  5. ReportHTML review report, saved to a chosen folder and searchable by product, file, verdict or severity
  6. PeopleA person reviews the findings and signs off

Stack

Python, OCR, Box API, Tkinter, HTML reports

Digital Health Report

A morning Slack report of the shelter animals that need medical attention: illnesses, observations and stool samples due, and handling notes.

It replaced a hand-compiled list that was sometimes missed when staffing or time ran short.

Case study Problem, workflow, stack

Problem

The medical team kept a hand-written list of animals that needed attention. It was compiled daily, printed and posted around the building, when time allowed. With limited staff and time, it was sometimes missed.

Workflow

  1. DataInternal medical databaseShelterluv scheduled report emails
  2. ProcessingGoogle Apps Script reads both sources and combines them into one report
  3. DeliveryFormatted message posted to Slack each morning
  4. PeopleRelevant staff read it in Slack

The report lists illnesses and medical notes, observations due, stool samples due, and handling notes. The screenshot is a test run with sample data, not real animals.

Stack

Google Apps Script, Slack, Shelterluv report emails, Drive API

Digital Walking Board

Staff and volunteers scan the QR code on a kennel and tap a dog out or back in. The board logs the time and suggests which dog goes next.

It replaced a dry-erase whiteboard, where outings and notes could be erased or missed. Each scan brings outing records and handling information into one view: a needed fecal sample, behavior notes, restricted areas.

Case study Problem, workflow, stack

Problem

Outings for 40 to 50 dogs, each going out 3 to 4 times a day, were tracked on a dry-erase whiteboard. Entries could be erased or missed, and handling notes lived somewhere else.

The board moves that record to the kennel door: scan, tap, and the time is logged.

Workflow

  1. ScanQR code on the kennel, opened on a phone
  2. RecordWalkYardParkBack in kennel
  3. LogTime and initials added to the dog's outing history
  4. BoardEvery kennel's status and time, and a suggested next outing
  5. PeopleStaff or a volunteer picks the next dog, following staff handling restrictions

The screenshots are a demo with 36 sample kennels. In the demo, initials identify the person but are not a secure login, and outings are recorded only in the demo. They do not show how the deployed board stores or shares its data.

Stack

HTML, JavaScript

Sidetone

A personal automation experiment: a lightweight Spotify controller for macOS.

Move the cursor to the screen edge or press a hotkey to control playback, search the library or open pinned favorites without leaving the app you are in.

Case study Problem, workflow, stack

Problem

Skipping a song or starting a playlist meant switching to the Spotify app, finding it, and switching back. Each switch is small, but it pulls attention away from the work in front of you.

Sidetone is a personal experiment in keeping those controls one gesture away.

Workflow

  1. OpenCursor to the screen edgeHotkey
  2. PanelNow playing, progress, playback controls and volume
  3. ChoosePinned favoritesSearch: songs, artists, albums, playlists
  4. ReturnBack to the app I was working in

This is the path through the app as a user sees it. It does not describe how work is split between AppleScript and the Spotify Web API.

Stack

Swift, SwiftUI, AppKit, AppleScript, Spotify Web API
